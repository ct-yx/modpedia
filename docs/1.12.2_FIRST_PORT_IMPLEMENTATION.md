# 1.12.2 第一版移植实现说明

## 目标

本分支面向 Minecraft 1.12.2 + Forge 兼容 API，并以 Cleanroom `0.3+` 为真实
运行时目标。客户端仍是 Java 8；需要 Java 21 的数据库、AI 和会话能力统一放在
用户级 `worker-baseline-3` 子进程中。

## 结构

```text
Minecraft Java 8
├── ClientProxy / LegacyAssistantScreen
├── ManualCatalogScanner + LegacyMarkdownCompiler
├── LegacyItemCatalogSyncService
├── LegacyTargetStore
├── LegacyJeiBridge（可选）
└── LegacyWorkerBridge ── JSONL/TCP ──> Java 21 Worker
                                      ├── SQLite / FTS
                                      ├── AI / 会话
                                      ├── Markdown 来源导入
                                      └── 静态任务库
```

客户端没有任何现代版本专用类；缺少可选配方、目标识别或手册 Mod 时，公共 UI、
本地来源扫描和 Worker 启动链路仍保持可用。

## 数据流

### 手册与 Wiki

1. `ManualCatalogScanner` 扫描实例目录和 `mods/**/*.jar`，记录来源格式、内容类型、
   语言、原始路径和指纹。
2. `LegacyMarkdownCompiler` 在后台生成
   `config/modpedia/knowledge/sources/modpedia-legacy-*`。
3. 原始 JAR、整合包作者文件和自定义文件不删除。
4. Worker 握手完成且后台转换结束后，才发送 `knowledge.rebuild`，由 Worker 构建
   当前版本的 `knowledge.db`/FTS。

### 旧版任务

静态任务：读取 `config/ftbquests/**`，转换到
`config/ftbquests/quests/modpedia_legacy/**`，供 Worker 的静态任务导入器使用。

运行时任务：只在 `search_tasks` 触发后读取当前存档：

```text
<world>/data/ftb_lib/players/<player>.dat       # 找 TeamID
<world>/data/ftb_lib/teams/<TeamID>/ftbquests.dat # Tasks 进度
```

`ftbquests.dat` 是压缩 NBT，不是文本 SNBT；读取器支持压缩 NBT、未压缩 NBT 和旧版
SNBT 回退。进度只通过内存 JSONL 返回，绝不写入静态任务库或知识库。

服务端安装本 Mod 且检测到 FTBQ 时，`LegacyFtbQuestEventBridge` 会在玩家登录、换维度和
重生时调用同一个读取器捕获一次服务端快照；FTBQ 的 `ObjectCompletedEvent$QuestEvent`
通过反射识别，完成任务只追加 `completed_quest_ids` 与 `timeline`，不重新扫描任务定义、
不写存档、不写 `knowledge.db`。快照使用 `LegacyFtbQuestSnapshotMessage` 发送到对应
客户端，客户端断开世界时清理远程快照。这样远程服务器不需要把任务文件暴露给客户端；
服务端未安装本 Mod 时仍保持“运行时进度不可用”的降级行为。

### 物品与可选联动

1. 物品注册完成后，客户端按每 Tick 32 个变体捕获显示名称和 Tooltip。
2. `namespace:item@metadata#nbt_sha256` 是 1.12.2 目录和令牌的身份；不会把旧版
   metadata 误当成 1.13+ 扁平化 ID。
3. K 键打开助手时冻结 Tooltip/准星目标；“插入”按钮负责写入
   `[[item:id|显示名|meta=n]]`。
4. 回答中的物品令牌 Shift+左键调用可选 JEI/同 API 配方界面；无该 Mod 时返回
   不可用状态而不阻止启动。

### 设置与历史会话

`LegacyAssistantScreen` 不创建额外 Minecraft Screen，而是在同一窗口内切换三个
面板：回答、助手设置和历史会话。设置页通过 Worker 读取/保存加密配置，支持：

- AI 回答与仅搜索模式；
- API 地址、模型、API Key 和流式开关；
- Chat Completions、Native Messages、Responses、Generate Content 四种格式；
- 获取模型列表、连接测试和搜索强度；
- API Key 失焦时只显示掩码，保存由 Worker 负责加密落盘。

历史页通过同一 JSONL 协议调用会话列表、新建、切换、清空和删除操作。回答请求
携带当前会话 ID；取消按钮发送同一请求 ID 的 `chat.cancel`，超时或错误状态回到
可重试的空闲状态，主界面的发送按钮会变为“重试”。

## Worker 安装约定

发布 Mod JAR 会内嵌 Worker 包；客户端首次启动时将其提取到用户级目录，目标实例
不会重复携带 Worker 依赖。用户级目录为：

```text
~/.modpedia/
├── ai.json
├── conversations/
└── worker/lib/worker-baseline-3/
    ├── modpedia-worker.jar
    └── 依赖 JAR（如 Worker 发布包需要）
```

当前 `modpedia-worker.jar` 对应 Worker 提交 `3e77dd0`，已覆盖 LF、CR 和 CRLF
JSONL 消息读取，并将 SLF4J API 2.0.9 放入 Worker 专用依赖目录。

开发或发布构建可以通过 `-Pworker_jar=/path/to/modpedia-worker.jar` 指定 Worker
构建产物；缺少 Worker 包时构建会直接失败，避免生成只有客户端桥接而无法启动 AI
链路的半成品 JAR。

可用以下方式指定 Java 21：

```text
系统属性：modpedia.worker.java=/path/to/java21
环境变量：MODPEDIA_WORKER_JAVA=/path/to/java21
```

没有 Worker 或没有 Java 21 时，助手仍可打开并回退到本地 Markdown 搜索；这不等于
AI/SQLite 链路已经执行成功，真实发行测试必须安装对应基线 Worker。

## 已知边界

- Cleanroom `0.3+` 尚未由本分支创建独立运行目录验证；必须使用真实整合包做客户端
  与 Dedicated Server 回归。
- 远程服务器的 FTBQ 任务文件不在客户端磁盘上；只有服务端也安装本 Mod 时，登录/换维度/
  重生快照和完成事件增量才会同步，否则只显示运行时进度不可用。
- 旧版 Guide-API、Lexicon、研究手册的可读内容先以资源转换或原始节点降级保留；
  依赖运行时对象注册的页型需要真实客户端验证跳转。
