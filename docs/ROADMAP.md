# ModPedia 后续开发路线

> 本文是后续开发的单一路线入口。`[x]` 表示已完成，`[~]` 表示代码已具备但仍需要真实环境回归，`[ ]` 表示未开始，`[-]` 表示暂缓或不进入当前版本。

## 1. 当前状态与版本基线

| 项目 | 当前值 |
| --- | --- |
| 当前发布构建 | `v1.0.0-fix` |
| GitHub 发布状态 | 修复预发布，等待真实客户端回归 |
| 下一版本方向 | `v1.1.0`，继续推进真实环境回归 |
| Minecraft | `1.21.1` |
| NeoForge | `21.1.244` |
| Java | `21` |
| 客户端 UI | 基于 NeoForge 原生 GUI API 自绘，无外部 UI 依赖 |
| Mod ID / 包名 | `modpedia` / `io.ctyx.modpedia` |

当前已经具备：

- Patchouli、GuideME、Modonomicon 手册资源扫描、转换、SQLite 检索和来源跳转；
- `zh_cn → en_us → neutral` 回退、中文双字词、英文词、ID 和关键词搜索；
- 自定义 Markdown 按稳定 ID、语言和 SHA-256 指纹启动增量导入；
- AI 回答、持续补搜、历史会话和“仅搜索”模式；
- 可移动、可缩放的半透明助手窗口及同层历史/设置页面。
- 统一 `knowledge.db` v7、可扩展 Wiki 来源、静态任务定义表、物品目录以及 FTB Quests/JEI/Jade 的可选联动基础；FTS5 external-content 与双语性能基准已加入。

当前主要风险不是基础功能缺失，而是大型整合包覆盖率、真实客户端 UI 回归、真实模型兼容性和发布维护流程仍需要证据。

| M3 | 中高 | AI 工具调用、补搜、流式和历史的可靠性 | `[~]` |

## 2.1 当前集成路线（I0–I3）

这条路线描述当前阶段新增的跨内容类型基础，完成后再继续 M0–M5 的稳定性和发布节奏。

| 阶段 | 内容 | 状态 |
| --- | --- | --- |
| I0 | 统一 `knowledge.db` v7、来源注册表、内容类型、物品目录和旧库删除重建 | `[x]` |
| I1 | FTB Quests 任务快照、任务 Wiki 和 `search_tasks` / `search_wiki` | `[~]` |
| I2 | 物品 ID 渲染、JEI 配方跳转、Jade 视线目标插入 | `[~]` |
| I3 | 手册三格式、可选联动、Dedicated Server 和真实整合包兼容回归 | `[~]` |

I1–I3 的 `[~]` 不表示缺少基础实现，而是仍需在真实安装版本中确认公开 API、任务进度事件、配方界面和目标识别结果。没有对应联动 Mod 时，核心客户端不应受到影响。

I2 还包含物品目录：客户端注册表冻结后按当前语言批量导入物品名称和完整 Tooltip，确认物品时作为 AI 和仅搜索模式的独立上下文；该目录与手册 FTS 保持分表结构。

## 3. M0：Beta 稳定性收尾

### 工作项

- 统一 README、安装说明、开发清单和发布说明中的版本状态；保留 `v1.0.0-beta.1`、`v1.0.0-beta.2` 作为历史技术标签并统一 Release 显示名称，从 `v0.2.0` 起使用 `0.x` 版本序列。
- 执行 `./gradlew test`、`./gradlew build`、`git diff --check`，并让发布工作流同时支持正式版和预发布版。
- 在 GUI Scale 4 下测试最小、默认和最大窗口，覆盖消息、输入、历史和设置页面。
- 回归标题栏拖动、四边/四角缩放、窗口边界、键盘焦点、滚动和正文来源标注。
- 分别测试 Patchouli、GuideME、Modonomicon，以及“手册框架 JAR 与内容模组 JAR 分离”的安装组合。
- 启动 Dedicated Server，确认不解析 `AssistantScreen` 和第三方客户端反射类。
- 使用真实模型回归多问题补搜、流式输出、取消、超时、错误重试和历史恢复。
- 使用 LangChain4j Community SQL 持久化 ChatMemoryStore；旧版上下文 JSON 自动迁移到本地 SQLite。
- 保存真实整合包测试记录、扫描覆盖率和已知问题。

本次 `v1.0.0` 已完成以上自动化、文档和发布链路工作；GUI Scale 4、Dedicated Server、三种手册真实跳转和部分大型整合包兼容项仍标记为 `[~]`，因为它们需要目标游戏实例的人工证据。

### 稳定版门槛

```text
自动化测试通过
构建产物可安装
git diff --check 通过
真实客户端 UI 回归通过
Dedicated Server 启动通过
三种手册来源可搜索并按来源能力跳转
仅搜索模式在空 API 配置下可用
```

## 4. M1：大型整合包知识库

### 工作项

- 使用真实大型整合包验证 JAR 数量、内容模组数量、手册来源数量和未识别资源路径。
- 将手册框架 JAR 和内容模组 JAR 分开统计，避免前置库影响正文覆盖率和来源排序。
- 补充更多自定义页面路径、配方、列表、链接和未知 JSON 节点适配。
- 继续以 SQLite 和完整 Markdown 作为事实源，不迁移为只保存摘要的结构。
- 保持中文、英文和 `neutral` 回退，确保多语言页面去重和版本信息不冲突。
- 增加数据库版本、损坏检测、staged 旁路重建、成功替换和失败恢复机制。
- 增加自定义 Markdown 的导入、导出、校验和冲突报告。
- 只有搜索基准超过目标时，才增加预构建段落索引；不提前引入向量数据库。

当前 FTS5 基准已覆盖真实当前实例语料和 10× 合成语料；下一步仍需用更多真实整合包验证
覆盖率和增量导入，而不是仅凭本机基准把 M1 标记为完成。

### 验收指标

```text
标准搜索 p95 ≤ 50 ms
搜索结果稳定排序且不重复
每篇文档最多返回一个最佳段落
中文、英文、模组 ID 和物品 ID 查询均可命中
10× 数据集可以完成启动导入和增量更新
```

## 5. M2：客户端 UI 稳定与可用性

### 工作项

- 建立 GUI Scale、窗口尺寸和字体比例的布局回归矩阵。
- 固化二级页面、输入框、正文来源标注、按钮和状态文字的统一绘制层级。
- 增加可重复的布局几何测试和截图回归记录。
- 优化窄窗口下的设置字段、历史列表、底部操作区和折叠输入入口。
- 完善键盘焦点、滚动、取消、关闭和鼠标命中区域。
- 保持当前原生 GUI 自绘实现，当前阶段不更换 UI 框架。
- 补充主题色、透明度、发光效果、高对比度和减少透明度的配置说明。

### 验收标准

- 最小窗口下文字、输入框和按钮不重叠；
- 历史和设置始终限制在父窗口内；
- 父窗口缩放时二级页面同步缩放并重新约束；
- 背景保持清晰，半透明面板和文字层次稳定；
- 关闭助手后游戏画面和世界运行状态恢复正常。

## 6. M3：AI 对话可靠性

### 工作项

- 保持 LangChain4j 作为 Chat Memory、工具调用、上下文预算和流式响应基础。
- 回归 Chat Completions、SSE、非流式回退和分段工具参数。
- 完成超时、取消、重试和错误状态展示。
- 验证证据不足时的多轮补搜、跨语言补搜、`has_more` 和重复查询抑制。
- 只允许模型引用本轮实际检索到的文档，并保留 SearchTrace。
- 完善上下文预算、来源去重、缺口说明和多问题分解。
- 对 API Key、请求头、日志和会话文件执行脱敏检查。
- 确保“仅搜索”模式完全跳过 API 配置校验和网络请求。

### 验收标准

- 配方、步骤、前置条件同时缺失时，模型会继续补搜；
- 达到搜索预算后明确列出资料缺口；
- 流式失败可以回退到完整响应；
- 取消和超时不会残留错误会话状态；
- 重启游戏后历史消息、正文来源标注和搜索轨迹可恢复。

## 8. M5：可选语义检索

只有以下条件全部满足时才进入本阶段：

```text
SQLite 规则检索已经优化
段落预索引仍无法达到 p95 目标
真实整合包中存在明确的语义召回缺口
```

候选方向：

- SQLite FTS 与向量检索混合；
- 整合包制作者在构建阶段生成向量；
- 嵌入模型和重排模型作为可选组件；
- 普通玩家默认继续使用规则检索。

模型、嵌入文件和 API Key 不默认捆绑进普通 Mod。

## 9. 统一指标与验证命令

| 指标 | 目标 |
| --- | --- |
| 单元/纯 Java 测试 | 全部通过 |
| 构建 | `./gradlew build` 通过 |
| 规则搜索 p95 | `≤50 ms` |
| 结果去重 | 每篇文档最多一个最佳段落 |
| 双语检索 | 中文、英文、`neutral` 回退稳定 |

| 服务端 | Dedicated Server 不解析客户端类 |

每次改动后的基础检查：

```bash
./gradlew test
./gradlew build
git diff --check
```

涉及客户端时补做实际游戏截图；涉及服务端时补做 Dedicated Server 启动；涉及手册适配时补做合成 JAR 和真实内容模组回归。

## 10. 暂缓功能与边界

- 暂不整体重写客户端 UI。
- 暂不把知识库迁移为只保存摘要或只保存向量的结构。
- 暂不默认下载手册、嵌入模型或远程知识库。
- 暂不在没有性能和召回证据时引入向量数据库。
- 暂不把内容模组正文错误归因于手册框架前置库。
